# senkyo-maps — 選挙・政治活動マップツール

ポスター貼付けとポスティングの進捗を管理する、**ブラウザだけで動く**静的マップツールです。
GitHub Pages でホスティングしており、URL を開くだけで誰でも使えます。

- **公開URL**: https://yukinobu-nakamura.github.io/senkyo-maps/
- 選挙と政治活動の歩き方: https://yukinobu-nakamura.github.io/senkyo-maps/arukikata/
- ポスターマップ: https://yukinobu-nakamura.github.io/senkyo-maps/poster/
- ポスティングマップ: https://yukinobu-nakamura.github.io/senkyo-maps/posting/
- 街宣マップ: https://yukinobu-nakamura.github.io/senkyo-maps/gaisen/

4ページはそれぞれ独立した並列URLです(どれかの配下ではありません)。note 等では貼りたいページのURLを個別に貼ってください。
旧URL(`/poster.html` 等)は新URLへリダイレクトするページを残してあります。

## 設計方針(チームみらい poster-map との違い)

[team-mirai-volunteer/poster-map](https://github.com/team-mirai-volunteer/poster-map)(GPL-3.0)
— 2024年都知事選の安野たかひろ陣営が運用したシステム — の**仕組みを参考にした独自実装**です。
コードは流用せず書き下ろしています(GPL の継承を避けるため)。

| 観点 | チームみらい版 | 本実装 |
|---|---|---|
| スタック | Next.js + Prisma + Supabase + Netlify/Vercel | 素の HTML/JS + Leaflet のみ(ビルド不要) |
| 状態の共有 | サーバ(DB)で全員リアルタイム共有 | 端末内 localStorage + CSV/GeoJSON ファイルの受け渡し |
| データ整備 | normalizer / pdf-converter / map2csv 等の専用ツール群 | 選管公表資料を CSV 化して画面から読込 |
| ポスティング描画 | Leaflet-Geoman + Supabase 保存 | Leaflet-Geoman + localStorage 保存 |

小規模陣営が「立ち上げ5分・運用コストゼロ」で使えることを優先し、サーバを持たない設計にしています。
数十人規模でリアルタイム共有が必要になったら、チームみらい版(GPL-3.0)の導入を検討してください。

## ポスターマップの使い方

1. 選挙管理委員会が公表する「ポスター掲示場一覧」を CSV にする
   - 必須列: `lat`(緯度)・`long`(経度)。任意列: `id`, `name`(名称), `address`(住所), `status`, `note`
   - 列名は日本語(`緯度`/`経度`/`名称`/`住所`/`備考` 等)でも自動認識
   - 住所しかない場合は、国土地理院 API 等でジオコーディングして緯度経度列を作る
2. 画面右上「📂 CSV読込」で読み込む
3. ピンをタップ → ステータス(未/予約/完了/要確認/異常)とメモを保存
4. 「💾 CSV書出」でステータス込みの CSV を保存 → 他メンバーへ共有(相手は読込)
5. **🏠 世帯数レイヤ**: 右上のレイヤボタンから、国勢調査2020・町丁目ごとの世帯数を重ねられる(ポスティングマップと同じレイヤ・同じ収録自治体。掲示場ピンより下に描くのでピン操作の邪魔をしない)

## ポスティングマップの使い方

1. 左のツールでポリゴン(配布区域)・線(配布ルート)を描く
2. 図形をタップ → 状態(予定/配布中/済)・**色(自動=状態色+8色)・濃さ(標準/薄め/最薄)**・担当・メモを保存
3. 「💾 GeoJSON書出」でファイル共有(相手は「📂 読込(GeoJSON/GPX)」で読込)。色・濃さもGeoJSONにそのまま乗る
   - **チーム統合(マージ)**: 書出時に自分の名前(👤で設定)と図形ID・更新時刻が自動付与される。読込は**賢い統合**=同じ図形(ID一致)は更新時刻の新しい方を採用、ID無しでも形が完全一致すればスキップ(同じファイルの再読込で増殖しない)。「誰の登録か」はポップアップと右上の登録者別件数に表示。運用: 各メンバーが書出→取りまとめ役が読込・統合→統合版を配り直す
   - **☁️ チーム同期(任意)**: ファイル受け渡しなしのリアルタイム寄り共有。**利用チーム自身のGoogleアカウント**にGoogle Apps Script+スプレッドシートを設置する方式(設置手順とコード: [`templates/team-sync/`](templates/team-sync/README.md))。データはチームのシートにのみ保存され、**作成者はサーバを運営せずデータも預かりません**。URL・トークンの管理はチームの責任
4. **GPX取込**: スマホの記録アプリ等で取った歩行ルート(GPX)を「📂 読込」で配布ルート(線)として取り込める。複数の trk/rte をまとめた**結合GPX**も各ルートとして取り込む(実装: `assets/common.js` の `gpxToGeoJSON()`)。取込ルートは既定で「薄め」表示(図形タップで変更可)
5. **📃 オブジェクト一覧**: 左上の📃で全図形の一覧(色・状態・登録者・地名/メモ)を表示。行タップでその図形へズーム+ポップアップ。管理表・世帯数レイヤの表示状況も末尾に表示
6. **📍 地名表示・🔍 地名検索**: 図形をタップすると町丁目名(丁目・字)をポップアップに自動表示(国土地理院 逆ジオコーダAPI・全国対応)。左上の🔍から地名・住所検索で地図ジャンプ(国土地理院 住所検索API。ポスター/街宣マップにも搭載)。いずれも無料・キー不要の試験公開APIのため、将来仕様変更の可能性あり
7. **🏠 世帯数レイヤ**: 右上のレイヤボタンから、国勢調査2020・町丁目ごとの世帯数コロプレス+数値ラベルを重ねられる(クリックで町丁目名・世帯数・人口と属性の内訳)。パネルの「色分け」で表示指標を切替できる: 世帯数/人口/日本人(概算)/外国人(実数・比率)/男女(実数・女性比率)/年少・生産年齢・老年・75歳以上(実数・比率)/年齢5歳階級(0〜4…100歳以上の21階級)。世帯数以外は表示中の値の等分位6段で塗り分け。少人口で国勢調査が秘匿処理した町丁目はグレー(データなし)
8. **🏠 世帯数CSV取込**: 自分の選挙区の世帯数一覧(スプレッドシート→CSV。列=名称・世帯数[必須]、人口・緯度・経度[任意])を取り込んで点表示。緯度経度が無い行は国土地理院の住所検索APIで位置を自動推定(400行まで・位置は目安)
9. **➕ 自治体追加リクエスト**: 世帯数レイヤの凡例・画面上部のリンクから、未収録自治体の追加をGitHub Issueでリクエストできる(区割の正確な記載を依頼・反映は約束しない旨を明記)
   - データ: `data/setai_<市区町村コード>.geojson`、収録一覧: `data/setai_index.json`
   - 追加方法: e-Stat 統計GISの境界データ(世界測地系緯度経度・shape形式)をDLし
     - 統計CSV(表2・表3)の台帳: `python3 build/make_stats_index.py`(初回のみ)→ `python3 build/fetch_stats_csv.py build/setai_stats_index.json <統計CSVディレクトリ>`
     - 1市区町村: `python3 build/make_setai_geojson.py <r2kaXXXXX.shp> data/setai_<code>.geojson --stats <統計CSVディレクトリ>`
     - 都道府県一括(code=2桁でDL): `python3 build/make_setai_geojson.py <r2kaXX.shp> --split data/ --stats <統計CSVディレクトリ>`
     - 最後に `python3 build/make_setai_index.py <shpディレクトリ> data/setai_index.json <更新日>` で一覧を作り直す
     - `--stats` を省くと属性(男女・外国人・年齢別)が付かず、その自治体は世帯数以外の指標が「データなし」表示になる
   - **収録一覧をHTMLに埋め込まない理由(配布済みファイルとの同期)**: 配布版(`dist/*.html`)はデータも一覧も公開URLから取得する。一覧を `setai_index.json` に置いておけば、**あとから自治体を足しても既に配ったHTMLがそのまま新しい一覧を拾う**(配り直し不要)。逆にHTMLへ埋め込むと配布済みのものが永久に古いままになる
   - ⚠️**互換性の約束**: `data/setai_<code>.geojson` の**パスと properties 名(`name`/`setai`/`jinko`/`key`/`units`、属性 `m`/`f`/`gk`/`a0`/`a1`/`a2`/`a75`/`ag`/`nf`/`tt`/`hi`/`gs`)は変えない・消さない**。配布済みHTMLがこのパスを直接叩いているため、リネームや削除は手元のファイルを壊す。項目の追加は安全(古い版は無視するだけ)
   - 属性の意味: `m`/`f`=男女、`gk`=外国人、`a0`/`a1`/`a2`/`a75`=15歳未満/15〜64/65歳以上/75歳以上、`ag`=5歳階級21値(総数)、`nf`=年齢不詳(>0のみ)、`tt`=統計表の総数(境界の`jinko`と異なる場合のみ)、`hi`=1 秘匿等データなし、`gs`=1 秘匿地域の合算受け皿。出典は令和2年国勢調査 小地域集計 表2・表3(取得台帳=`build/setai_stats_index.json`)。日本人人口は直接の統計が無く「総数−外国人」の概算(国籍不詳を含む)として表示側で計算
   - 世帯数は国勢調査の**総世帯数**(一般世帯+施設等の世帯)ベース。横浜市18区の合算は 1,753,081世帯・3,777,491人で、横浜市公表の令和2年国勢調査確定値と一致することを確認済み
   - **1町名=1図形**: 丁目を持たない大きな町は、国勢調査の集計単位として `KIHON2`(丁目・字番号)で分割されるが**名称は同じまま**になる(例: 泉区 岡津町=2区分、戸塚区 戸塚町=4区分、泉区 和泉町=5区分)。この分割は住居表示に対応せず現地に手がかりが無いため、同一市区町村内の**同じ町名を1フィーチャへ統合**して世帯数を合算する(岡津町=3,965+461=4,426世帯)。丁目は名称が異なるので統合されない。`properties.units` に合算した区分数が入り、2以上ならポップアップに注記が出る
   - **同一町丁目が複数境界に分かれる場合の扱い**: 1つの町丁・字等番号に境界が複数あるとき、e-Stat は `KIGO_E` に E1/E2/… を付け、**人口・世帯数は E1 が代表して持ち E2 以降は 0** にする(定義書 注2・注25・注26。二重計上の回避)。変換スクリプトは同一 `KEY_CODE` を1フィーチャ(MultiPolygon)へ統合してこれを吸収する(未統合だと E2 以降が「0世帯」と誤表示される)。`AREA_MAX_F='M'` は面積最大であって E1(人口順)とは別物なので値の保持者の判定に使わないこと。詳細は `build/make_setai_geojson.py` の docstring
   - クレジット: 政府統計の総合窓口(e-Stat) 国勢調査(2020年)小地域集計・小地域境界データを加工して作成(画面の凡例・ポップアップに表示)

## 注意事項

- データは**端末ごと**(ブラウザの localStorage)に保存されます。ブラウザのデータ消去で消えるため、こまめに書出でバックアップしてください
- ファイル選択ダイアログは**すべてのファイルを選択可**にしています(Android のファイルピッカーが `.geojson` 等の拡張子を認識せず選択できない問題への対応)。形式はファイルの中身で自動判定し、不正なファイルはエラー表示します
- 同梱のサンプル掲示場データはダミーです。実在の掲示場所とは無関係です
- 公職選挙法上、選挙運動用ポスターの掲出は掲示場・期間等のルールがあります。運用は各自治体の選管の案内に従ってください
